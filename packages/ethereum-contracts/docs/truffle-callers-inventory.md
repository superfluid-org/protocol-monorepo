# Truffle callers and capability inventory

Discovery snapshot: 2026-11-10, `feature/truffle-removal` on PR #2257 head `7d26f130`. Read-only research; no builds, tests, transactions, signatures, broadcasts, or proposals were run. `yarn why -R` was run with Yarn 4.18.0/system Node 26 after the coordinator reported Nix unavailable. Package/lockfile observations below are static, not clean-install results.

**Binding decisions:** retire js-sdk from active workspaces/build/tests (not npm deprecation); remove published `build/truffle` in **1.16.0**, retain `build/hardhat`; retain fresh persistent deployments and upgrades; manual operator use is real; all 16 metadata networks remain supported, excluding deprecated degenchain. These are user decisions from the issue handoff, not inferred from CI usage. Production shapes/admin routes must be reconciled with the companion onchain inventory before implementation.

Disposition vocabulary: **supported** = preserve capability using an existing replacement; **simplified** = preserve outcome with a smaller interface/new implementation; **retired** = deliberately remove mode or infrastructure; **not implemented** = explicit failing command before side effects, not a successful no-op; **covered by devchain tooling** = keep on local/test deployer path. All proposed filenames/commands marked **new** below are design proposals, not existing implementations.

Source paths in tables are relative to repository root; short paths `ops-scripts/`, `tasks/`, `new-ops-scripts/`, `foundry-scripts/`, `test/`, `dev-scripts/` mean `packages/ethereum-contracts/`. Links resolve from this document. “Operator” means the handoff explicitly establishes manual usage, but no per-command execution history is available. “No additional caller found” is a source-search observation, not proof of disuse.
